# Glossary

**ACID 2.0** — associative, commutative, idempotent, distributed; operations with these properties stop caring about order and duplication (Ch 3)
**At-least-once delivery** — the broker may deliver a message more than once, never fewer (Ch 3, Ch 4)
**At-most-once delivery** — a message is never duplicated but may be lost (Ch 4)
**Acknowledgement** — the consumer telling the broker a message is safely handled; its timing decides the real guarantee (Ch 6)
**Backlog** — undelivered messages accumulating when consumers fall behind production (Ch 10)
**Binding** — the rule connecting an AMQP exchange to a queue (Ch 6)
**Buffered Event Ordering** — reordering events by an incrementing value with a bounded wait for gaps (Ch 5)
**Competing consumers** — several consumers on one queue, each message handled by exactly one (Ch 4, Ch 6)
**Composite identifier** — producer identity plus a locally increasing counter; unique without coordination (Ch 8)
**Coordination point** — a shared resource every producer must consult; simple, and a scaling and availability limit (Ch 8)
**Correlation identifier** — an id carried on a message so a later message can be matched to it (Ch 6)
**Data locality** — arranging that related events are processed together (Ch 9)
**Dead-letter queue** — a side queue for messages that exhausted their processing attempts (Ch 3)
**Delta event** — an event carrying a change rather than a resulting value; not idempotent (Ch 2, Ch 4)
**Distributed lock** — pessimistic cross-process coordination; adds a component and a new failure mode on expiry (Ch 2)
**Dual-write problem** — writing to a store and a broker without a shared transaction; either can succeed alone (Ch 3)
**Durable queue** — a queue that survives broker restart and consumer disconnection (Ch 6)
**Entity event** — keyed on a thing's id, carrying its full state; only the latest is needed for current state (Ch 9)
**Event time / processing time / ingestion time** — when it happened, when it was handled, when it entered the system (Ch 10)
**Exactly-once processing** — the business effect occurs once despite repeated delivery (Ch 4)
**Exchange** — the AMQP routing element that producers publish to (Ch 6)
**Exclusive queue** — destroyed when its connection closes; correct for consumers that do not care about missed messages (Ch 6)
**Freshness rule** — the comparison deciding whether an incoming message is newer than stored state (Ch 1, Ch 2)
**Hotspotting** — an uneven key distribution sending a disproportionate share of traffic to one partition (Ch 2)
**Idempotency** — repeated execution yields the same result as a single execution (Ch 3, Ch 4, Ch 7)
**Keyed event** — carries a key for routing and locality but does not describe an entity (Ch 9)
**Late-arriving event** — arrives after the processor has moved past its time (Ch 10)
**Liveliness** — the guarantee that something good eventually happens; state does converge (Ch 1)
**Materializing state** — applying entity events in order, upserting by key, so the table holds current state (Ch 9)
**Optimistic concurrency** — allow the conflict and reject the loser at write time with a condition (Ch 2)
**Outbox pattern** — write the outgoing message in the same transaction as the state change; publish separately (Ch 3)
**Partition key / routing key** — the field deciding which queue or consumer an event lands on (Ch 2, Ch 5)
**Pessimistic concurrency** — prevent the conflict, by locking or by routing so it cannot occur (Ch 2)
**Poison event** — an event that fails every processing attempt (Ch 3)
**Read-modify-write hazard** — reading, computing, then writing back, losing a concurrent update (Ch 8)
**Repartitioning / shuffle** — rekeying a stream; the main manufacturer of out-of-order events (Ch 10)
**Safety** — the guarantee that nothing bad happens; no invalid state is written (Ch 1)
**Sequential Convoy** — split a stream into substreams by key hash, process in parallel, optionally merge back by sequence number (Ch 5)
**Single writer principle** — each event stream has exactly one producing service (Ch 9)
**Staleness window** — how far behind a derived view may fall before it is a defect (Ch 1)
**Stream time** — the highest event time observed so far in a stream (Ch 10)
**Table-stream duality** — a stream folds into a table; a table's changes unfold into a stream (Ch 9)
**Time skew** — independent instances progressing at different rates, producing disorder (Ch 10)
**Unkeyed event** — a singular statement of fact with no key (Ch 9)
**Upsert** — insert if absent, update if present (Ch 9)
**Watermark** — an assertion that no event older than a given time will arrive (Ch 5, Ch 10)
