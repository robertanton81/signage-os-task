## Problem

The consistency spec fixes what a message carries, how "newer" is decided and how state is stored. It leaves to step 2 the choices that turn that into code: the wire framing between device and ingest, the validation library that also produces the TypeScript types, the logger, how configuration is loaded and which variable names exist, and where the storage document types and the queue and collection names live. Every service imports the results, so they must be decided once, with versions pinned and documentation verified, before any service is written.

| 1   | Wire framing between device and ingest                | **Newline-delimited JSON (NDJSON) over the raw TCP socket.** One message is one JSON object encoded as UTF-8 and terminated by `\n`. A frame is complete only when its newline has arrived; whitespace-only lines are ignored; a line longer than `MAX_FRAME_BYTES` (65 536) is a protocol violation — the decoder throws `FrameTooLongError`, resets, and ingest closes that connection; bytes left without a newline when a connection closes are dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Two facts make the newline an unambiguous terminator. Inside string values a compliant generator must escape every control character, so a raw U+000A can never come from a `message` or `code` field (RFC 8259 §7 and §10, Research). Outside strings the JSON grammar does allow line feeds as insignificant whitespace (§2), so the guarantee for the whole message comes from the encoder: `encodeFrame` is the only producer of frames in this system and calls `JSON.stringify(message)` without the `space` argument, which inserts no whitespace at all (MDN, Research). Compact JSON is therefore part of the wire contract: a foreign device that pretty-prints its JSON is rejected line by line as invalid JSON, and the emulator uses `encodeFrame`. A trailing `\r` is insignificant whitespace to `JSON.parse` (§2), so CRLF clients work unchanged. The stream is readable with `nc` and in packet captures, which helps the technical discussion and debugging. ## Chosen Approach

`packages/shared` becomes the contract and nothing more: one zod schema is the source of the message type and of the storage document types; three pure helpers (`messageIdentity`, `orderKey`, `isNewer`), one frame codec and one decoder are the only logic; the broker and database names are constants; a pino factory and a zod-based environment loader are the cross-cutting helpers. The package performs no I/O and depends on no client library, so every service and every test imports it without a broker or a database.

**Why this over alternatives:** one library (zod) serves both the wire contract and the configuration; one logger; nothing in shared needs a mock. Each piece can be explained in one sentence in the technical discussion, and each has a unit test that names a concrete input and its outcome.

### Message contract (`message.ts`)

The schema is the consistency spec's `TelemetryMessage` written in zod. Rules: all five envelope fields present with the given types and ranges; `v` is the literal `1`; `deviceId` matches `^[A-Za-z0-9_-]+$` and is 1–64 characters; `sessionId` and `seq` are safe integers ≥ 1; `occurredAt` is a safe integer; `type` is one of `status`, `metrics`, `counters`, `diagnostic`; the payload is a strict object for that type; numbers are finite; `counters` values are integers ≥ 0; `code` is 1–64 and `message` up to 1 024 characters. Unknown keys anywhere are rejected. Exported: `telemetryMessageSchema`, the four payload schemas, `TELEMETRY_EVENT_TYPES`, the types `TelemetryMessage`, `TelemetryEventType`, `TelemetryMessageOf<T>`, `PayloadOf<T>`, `StatusPayload`, `MetricsPayload`, `CountersPayload`, `DiagnosticPayload`, and the bound constants. The exact code is in the plan (task 2).

### Identity and order (`identity.ts`)

`MessageIdentity = { deviceId, sessionId, seq }`, `OrderKey = { sessionId, seq }`. `messageIdentity(m)` returns `` `${deviceId}:${sessionId}:${seq}` `` (log field, AMQP `messageId`, `alerts._id`). `orderKey(m)` returns `[sessionId, seq]`. `isNewer(candidate, stored)` is the single definition of "newer": `candidate.sessionId > stored.sessionId || (candidate.sessionId === stored.sessionId && candidate.seq > stored.seq)`; equal keys are not newer. The processing pipeline builder (step 5) is derived from it and its test runs the same cases. `extractRawIdentity(value)` returns the subset of the three fields present on an unvalidated value with the right primitive type, for log lines about rejected input.

### Framing (`framing.ts`)

`encodeFrame(message)` → `Buffer` of `JSON.stringify(message) + '\n'` in UTF-8; no `space` argument, so the JSON text is one line (MDN, Research) — compact JSON is part of the wire contract, and a pretty-printed message from a foreign client is rejected line by line as invalid JSON. `FrameDecoder` keeps the unfinished tail between `push(chunk)` calls and returns the complete lines (without their newline) in order; whitespace-only lines are skipped; a trailing `\r` is left in place because `JSON.parse` accepts it as whitespace (RFC 8259 §2). `push` throws `FrameTooLongError { bytes, limit }` when a complete line, or the buffered tail, exceeds `maxFrameBytes` (constructor argument, default `MAX_FRAME_BYTES` = 65 536) and clears its buffer first. Ingest always closes the connection on this error (decision 1); the cleared buffer only means the decoder instance is not left in a broken state, which the unit test checks. `pendingBytes` exposes the buffered tail length for the log line at connection close. Bytes that are not valid UTF-8 become U+FFFD replacement characters (Node Buffer docs, Research); the frame then fails as invalid JSON or as an invalid string value, never as an exception.

### Decoding (`decode.ts`)

```ts
type DecodeResult =
  | { ok: true; message: TelemetryMessage }
  | { ok: false; reason: 'invalid_json' | 'invalid_schema'; detail: string; identity: RawIdentity };
```

`detail` is the `JSON.parse` error message, or every zod issue as `path: message` joined by `; ` (`(root)` for an empty path). `identity` is `extractRawIdentity` of the parsed value (empty for invalid JSON).

## Consistency & Failure Modes

Shared performs no I/O, so the six invariants are enforced elsewhere; this package supplies the pieces those mechanisms are built from:

| Invariant (`CLAUDE.md`)                   | What shared contributes                                                                                                                                           | Proved by                                                                                                           |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1. Logical order wins                     | The schema guarantees `sessionId` and `seq` are present, integer and ≥ 1; `isNewer` is the single freshness rule the processing update is derived from.           | `message.test.ts` (rejections), `identity.test.ts` (six ordered cases); step 5 pipeline test agrees with `isNewer`. |
| 2. Duplicates have no effect              | `messageIdentity` (deterministic identity string), `EVENTS_IDENTITY_INDEX` (the unique index definition), `DUPLICATE_KEY_ERROR_CODE`, equal keys are "not newer". | `identity.test.ts`; steps 5 and 7 against MongoDB.                                                                  |
| 3. Atomic state updates                   | `DeviceStateDocument` is one document with per-section watermarks, the shape the conditional single-document update needs.                                        | `contract.test-d.ts` (shape); step 5/7 integration tests.                                                           |
| 4. Parallel across devices, serial within | Nothing device-specific is held in shared; the contract makes processing order irrelevant.                                                                        | —                                                                                                                   |
| 5. Minimal throughput cost                | The decoder is one pass over each chunk; validation is one `safeParse` per message (trade-off T12).                                                               | —                                                                                                                   |
| 6. Both services scale, ingest stateless  | `FrameDecoder` state is per connection and dies with it; `loadConfig` and the logger hold no per-device state.                                                    | `framing.test.ts`                                                                                                   |

Failure behaviour of the helpers:

| Input                                                       | Behaviour                                                                                                                               |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Frame is not valid JSON                                     | `decodeTelemetryMessage` → `{ ok: false, reason: 'invalid_json', detail, identity: {} }`; caller logs and drops.                        |
| Frame violates the schema                                   | `{ ok: false, reason: 'invalid_schema', detail: 'payload.temperatureC: …', identity }`; caller logs with the identity fields and drops. |
| Line longer than `MAX_FRAME_BYTES`                          | `FrameDecoder.push` throws `FrameTooLongError`, buffer cleared; ingest logs and closes the connection.                                  |
| Chunk boundary inside a multi-byte character                | Bytes are concatenated before decoding; the frame decodes correctly.                                                                    |
| Frame contains bytes that are not valid UTF-8               | `Buffer.toString('utf8')` substitutes U+FFFD, never throws; the frame is rejected as invalid JSON or as an invalid string value.        |
| Device sends pretty-printed (multi-line) JSON               | Each line is rejected as invalid JSON and logged; compact JSON is part of the wire contract (decision 1).                               |
| Connection closes with an unfinished line                   | The tail is dropped; `pendingBytes` lets ingest log how many bytes were lost (trade-off T3, device-side fire-and-forget).               |
| Environment variable unset or empty                         | Its default applies; a required variable without a default → `ConfigError` naming it; the service exits at startup.                     |
| Environment variable invalid (`abc`, `0` below the minimum) | `ConfigError` with `NAME: problem`; all problems are listed at once.                                                                    |

Delivery semantics are unchanged from the consistency spec (at-least-once between ingest and storage, fire-and-forget device to ingest, exactly-once effect at the storage boundary).

## Scaling

A library has no instances. Two costs it adds per message are named: one `safeParse` per message in ingest and again in processing (decision 2 trade-off; measured only if a bottleneck appears), and one linear scan per socket chunk in the decoder. Neither holds state across devices, so nothing here limits horizontal scaling.

## Alternatives Considered

### Length-prefixed binary framing

A 4-byte big-endian length before every JSON body. Handles arbitrary payload sizes without scanning for a delimiter and detects truncation exactly. Costs a custom encoder and decoder on both sides and makes the stream opaque to `nc` and packet captures. Rejected for this scope; documented as the upgrade path for larger payloads (T11).

### WebSocket or HTTP

Framing, ping/pong and a client library for free, at the price of an HTTP upgrade handshake, a dependency in ingest and the emulator, and a protocol that machine clients do not need. The assignment says "socket connections"; raw TCP with NDJSON is the smallest reading of it.

### ajv (JSON Schema) instead of zod

Faster validation and a language-neutral schema document. The TypeScript type would have to be written by hand or generated by a second library, which breaks the "types derived from the schema" rule. Named as the upgrade path if validation cost is measured as the bottleneck.

### Full per-app configuration schemas in shared

One place for every variable. Rejected because shared would then carry ingest, processing and emulator knobs, which are app decisions; the names are still fixed in one place (`.env.example`).

### dotenv

Redundant with Node's `--env-file` flags; Compose sets the environment in containers.

### `@types/amqplib` and rabbitmq-client

Not needed and rejected respectively — see decision 10.
